# Karpathy LLM 编码指南

> 来源：Andrej Karpathy, 2026. 社区提炼为 `andrej-karpathy-skills`。
> 本项目前后端 CLAUDE.md 已内置此规范。此文件为团队统一存档。

## 1. Think Before Coding（先想再写）

- 明确陈述假设，不确定就提问
- 存在歧义时枚举所有解释，不要默默选一种
- 遇到不清楚就停下来，命名困惑点
- 有更简单的方案时主动提出、敢于 push back

## 2. Simplicity First（简洁优先）

- 不添加需求之外的功能
- 不为单次使用创建抽象
- 不加未要求的"灵活性/可配置性"
- 200 行能写成 50 行就重写

## 3. Surgical Changes（手术式修改）

- 不顺手"改进"邻近代码、注释或格式
- 不重构没坏的部分
- 匹配现有风格，即使你更倾向另一种写法
- 发现无关死代码只提不删
- 每一行改动都能追溯到用户请求

## 4. Goal-Driven Execution（目标驱动执行）

- "修 bug" → 先写复现测试，再让它通过
- "加验证" → 先写无效输入测试，再让它们通过
- 多步任务：`[Step] → verify: [check]`
- 给成功标准，而不是给步骤，让 LLM 自己循环执行
