# 决策 #009: HRM 集成方案选型

- **日期**: 2026-05-17
- **决策者**: Architect
- **上下文**: 用户要在天津宏观世纪ERP中直接使用分路 HRM 模块，不切换系统

## 选项

| | A: iframe | B: API网关 | C: 代码迁移 | D: 混合 | E: 共享DB |
|---|---|---|---|---|---|
| 工期 | 3-5天 | 2-4周 | 3-6月 | 1周+分批 | 2-3月 |
| 分路改动 | 极少 | 无 | 无 | 按需 | 无 |
| 前端改动 | 极低 | 高 | 高 | 渐进 | 高 |

## 选择：方案 D（渐进混合）

阶段 1：iframe 全量嵌入（本期，4.5 天）
阶段 2+：高频模块逐步代码迁移

## 阶段 1 关键技术选择

1. **菜单统一** — 天津宏观世纪前端改调 HRM `GetListByRole` API，通过天津宏观世纪后端代理转发
2. **Token 桥接** — 天津宏观世纪后端用预设账号调分路登录 API 获取 Token
3. **appContext 断裂修复** — 代理页面（hrm-proxy） + postMessage 注入上下文
4. **Token 过期防控** — 分路 baseService.js 加 `?embedded=true` 参数（~20行），过期发 postMessage 而非跳转登录页

## 理由

- 阶段 1 1 周内可用，风险最低
- 不改分路 70+ 页面的核心逻辑
- 菜单/权限统一到 HRM 体系，一套配置管理
- 为后续模块迁移留出时间窗口
