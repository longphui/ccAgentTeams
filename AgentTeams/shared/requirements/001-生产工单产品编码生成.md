# 需求 #001：生产工单产品编码生成

- **日期**: 2026-05-13
- **提出方**: Architect（与用户沟通确认）
- **状态**: 待分派

---

## 一、需求概述

分路系统中，根据生产工单（ProduceWorkOrder）为每个生产的产品生成唯一编码，一物一码。编码规则由用户通过 CodeGenerator 功能自行配置（BizCodeIdentifier = "ProductCode"），本需求只负责触发编码生成和查询。

---

## 二、核心流程

```
工单生产 N 件产品（PlannedProductionNum）
  → 用户点击"生成编码"按钮
    → 弹框确认（显示工单号、产品名、生成数量）
      → 调 GenerateCode API：
          CodeSign: "ProductCode"
          Count: N
          Objects: [
            { ObjectType: "ProduceWorkOrder", ObjectId: 工单Id },
            { ObjectType: "Product", ObjectId: 产品Id }
          ]
        → 生成 N 条 CodeRecord
        → 刷新列表
```

**一物一码**：Count = 工单的 PlannedProductionNum。

**赋码对象多维度**：每条 CodeRecord 关联两个赋码对象 — ProduceWorkOrder（生产上下文）+ Product（产品信息）。

## 三、前端设计

### 3.1 页面路径

```
views/productionManage/commonProductionStages/generatorProductCodes/
├── index.html       # 三 Tab 主页面
└── codeList.html    # 编码查询弹窗
```

### 3.2 Tab 结构

| Tab | 内容 | 数据来源 | 操作列 |
|-----|------|----------|--------|
| 未生成编码 | 编码数=0 的工单 | `GetPageListForCodeGen` | 「生成编码」→ 确认弹窗 → 调 GenerateCode |
| 已生成编码 | 编码数>0 的工单 | `GetPageListForCodeGen` | 「查询编码」→ 打开 codeList.html |
| 编码记录 | 全部 CodeRecord | `GetCodeRecords`（扩展多条件查询） | 查看详情 |

### 3.3 工单列表列

| 列 | 来源 |
|----|------|
| 工单编号 | WorkOrderNo / FactoryNo |
| 产品名称 | ProductName |
| 生产数量 | PlannedProductionNum |
| 工单状态 | Status → StatusName |
| 操作 | 生成编码 / 查询编码 |

> **设计决策（2026-05-13）**：不显示「编码数量」列。编码数量要么等于生产数量（已生成），要么为 0（未生成），无中间态，显示无意义。同时移除 COUNT 联查，提升查询性能。

### 3.4 生成编码确认弹窗

```
"确认生成编码？"
工单编号：XXX
产品名称：XXX
生成数量：N 件
[确认] [取消]
```

### 3.5 编码查询弹窗（codeList.html）

> 弹窗针对**某一个工单**的产品编码，查询条件从简。

**筛选条件**：编码值（模糊匹配）

**表格列**：序号、编码值、生成时间

**分页**：后端分页，固定 `ObjectType="ProduceWorkOrder"` + `ObjectId=工单ID`

### 3.6 编码记录 Tab（index.html Tab3）

> 面向**全部工单**的编码记录，需要多条件筛选。

**筛选条件**：工单编号、商品名称、编码值、生成时间范围

**表格列**：序号、工单号、商品Id、商品名称、商品规格、编码值、生成时间

## 四、后端改动

### 4.1 ProduceWorkOrder 模块

| 接口 | 方法 | 说明 |
|------|------|------|
| `GetPageListForCodeGen` | POST | 工单列表 + 联查 CodeRecordObject 统计编码数量 |
| 入参 | `WorkOrderProductionPageSearchInput` + `codeGenStatus` (0=未生成/1=已生成) | |
| 出参 | `ProduceWorkOrderOutput` + `GeneratedCodeCount`(int) | |

**Service 层**：`IProduceWorkOrderService` + `ProduceWorkOrderService`
**Controller 层**：`ProduceWorkOrderController`，使用 `[PPMLog]`（生产管理模块）

### 4.2 CodeGenerator 模块（扩展）

| 接口 | 方法 | 说明 |
|------|------|------|
| `GetCodeRecordsByObject` | POST | 根据赋码对象查询编码，纯通用接口 |

**入参**：
```csharp
class CodeRecordSearchInput {
    ObjectPair[] Objects,   // [{ObjectType, ObjectId}] 数组，匹配任一
    string CodeValue,       // 编码值（可选，模糊匹配）
    DateTime? StartTime,    // 生成时间起
    DateTime? EndTime,      // 生成时间止
    int SkipCount,
    int PageSize,
}
```

**设计原则**：
- 接口只接受底层通用参数（Objects 数组），不包含业务字段（WorkOrderNo、ProductName）
- 业务条件由调用方在外层转换：先查业务表得到 Id → 构造 ObjectPair[] → 传入
- 查询走 CodeRecord.Objects 属性关联，避免 CodeRecordObjects 全表扫描

**Service 层**：`ICodeGeneratorService` + `CodeGeneratorService`
**Controller 层**：`CodeGeneratorController`，使用 `[CommonLog]`

## 六、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 不修改现有工单 API | 新增 GetPageListForCodeGen | 手术式修改，不影响已有功能 |
| 编码不回写工单 | 仅存 CodeRecord + CodeRecordObject | 一物一码，N 条编码无法存入单字段 |
| Controller 日志 | Produce 用 `[PPMLog]`，CodeGenerator 用 `[CommonLog]` | 按模块归属选择日志属性 |
| 确认弹窗 | 调用 GenerateCode 前弹窗确认 | 防止误操作，明确告知生成数量 |
