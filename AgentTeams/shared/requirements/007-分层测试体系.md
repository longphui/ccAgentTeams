# 需求 #007: 分层测试体系

- **日期**: 2026-05-21
- **状态**: 分析中
- **工期**: 1 天

## 目标

将 QA 测试从"纯手工浏览器验证"升级为"Playwright 自动化 + 真实后端联调"的分层体系。解决两个痛点：① QA（AI agent）无法真正"打开浏览器看"，只能截图识别静态页面；② 当前全 Mock 模式测的是理想化前端，后端字段变更不会报错。

## 范围

### 包含

- QA 角色定义从手工测试切换为 Playwright 自动化测试
- Playwright 配置支持 Mock 模式 / 真实后端双模式切换
- 现有 22 个 spec 文件支持 `USE_MOCK` 环境变量控制
- 分层测试流程：API curl → Playwright Mock → Playwright 真实后端
- 联调阶段 `headless: false` 可视模式，用于截图/录屏证据

### 不包含

- CI/CD 流水线对接（中期规划）
- 前后端单元测试框架搭建（Vitest/NUnit，另有需求）
- 新增业务模块的 UI 交互测试覆盖（随功能开发逐步追加）

## 用户故事

1. 作为 QA，我希望一套 Playwright 脚本既能 Mock 模式下跑（不依赖后端），也能切到真实后端跑（联调验证），以便同一套用例覆盖两个阶段
2. 作为 Architect，我希望 Developer 和 Developer1 提测后，QA 能自动化验证，减少人工沟通成本
3. 作为 Developer，我希望联调阶段 QA 跑真实后端时发现问题自动截图/录屏，而不是收到模糊的"数据不对"描述

## 验收标准

| # | 场景 | 操作 | 预期结果 |
|---|------|------|---------|
| 1 | Mock 模式 | `USE_MOCK=true npx playwright test` | 所有 spec 用 `page.route()` Mock 跑通 |
| 2 | 真实后端模式 | `USE_MOCK=false npx playwright test` | 跳过 Mock 注册，直接请求真实后端 |
| 3 | 可视调试 | `npx playwright test --headed` | 浏览器窗口可见，可观察操作过程 |
| 4 | 截图证据 | 测试失败 | 自动截图到 `playwright/screenshots/` |
| 5 | QA 定义更新 | 查看 `agent-qa.md` | 流程描述为分层测试，不再写"手工浏览器验证" |

## 技术决策

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| Mock 开关方式 | 环境变量 / 配置文件 / 命令行参数 | 环境变量 `USE_MOCK`（默认 true） | spec 内 `if (process.env.USE_MOCK !== 'false')` 判断，简单不侵入 |
| 可视模式 | headless 配置 / --headed CLI | `--headed` CLI 参数 | Playwright 原生支持，不改配置 |
| 双 project | 单 project + 环境变量 / 两个 project | 单 project + 环境变量 | 减少配置复杂度，环境变量已足够区分 |
| QA 角色定位 | 手工测试 / 自动化测试 | 自动化测试（Playwright 执行者） | QA 是 AI agent，无法真正操作浏览器，Playwright 是正确工具 |
